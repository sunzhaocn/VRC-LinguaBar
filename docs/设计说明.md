# VRC 语伴设计说明

VRC 语伴的核心是一条简单的输入路径：**游戏中按 Y → 桌面输入条选词 → OSC 聊天气泡**。文字编辑交给标准 Qt 控件，候选词交给 Windows 输入法，游戏只接收确认后的文字。

## 代码在哪里

`linguabar` 包按职责组织代码：

| 文件 | 负责什么 |
|---|---|
| `cli.py` | 启动入口、帮助信息与平台检查 |
| `config.py` | 默认值、命令行参数与参数检查 |
| `text.py` | 单行文字清理、UTF-16 长度计算与截断 |
| `win32.py` | Windows API、窗口和进程识别、输入法状态、焦点获取 |
| `guards.py` | 菜单、鼠标与相机状态的唤醒判断 |
| `hooks.py` | Y 键监听、前台窗口事件与跨线程唤醒信号 |
| `osc.py` | 聊天 OSC 发送和相机状态接收 |
| `ui.py` | 输入条、输入法事件、实时同步与关闭流程 |
| `app.py` | 应用生命周期、游戏窗口发现、托盘和退出清理 |
| `startup.py` | 当前用户自启设置、游戏进程监视和日志 |

`python -m linguabar` 和根目录的 `vrchat_linguabar.py` 都可启动应用。根目录的 `startup.py` 是自动启动监视器入口。分发源码时，需要保留 `linguabar` 目录和这两个入口文件。

## 一次输入如何完成

1. 控制器发现符合窗口类、可执行文件名和可选 PID 条件的 VRChat 窗口。
2. 键盘钩子收到 Y，判断前台窗口、菜单和相机状态。
3. 可以输入时，钩子接管这次按键，通过 Qt 信号通知主线程。
4. 主线程再次核对目标，创建输入条并获取编辑框焦点。
5. 系统输入法处理组词与选词，确认后的文本同步到聊天气泡。
6. Enter 发送，Esc 或外部失焦取消；关闭流程停止计时器、处理 OSC 消息并回收窗口。

检测到菜单或相机时，钩子会吞掉这次 Y；检测到原生文本控件时，则保留字母输入。键盘钩子不负责创建窗口或发送网络消息，界面操作集中在 Qt 主线程。

## 输入法与焦点

编辑器基于 PyQt5 `QLineEdit`，使用 `QInputMethodEvent` 区分预编辑内容和已提交文字，并通过 Windows IMM API 补充查询组词状态。

组词期间，Enter 和 Esc 优先交给输入法。候选提交后有 80 毫秒的发送保护间隔，避免确认候选时顺带发出整句。工具不生成候选词，也不改变输入法词库。

输入条必须拿到真实编辑焦点才能使用。必要时会短暂连接窗口输入队列，并在完成后解绑；获取焦点失败则关闭本次输入条。

失焦判断由 Windows 前台切换事件和 Qt 窗口停用事件触发。输入条自身的弹窗，以及部分已识别的微软输入法候选窗，可以保留输入会话。切到其他应用时取消输入，第三方独立候选窗需要单独确认兼容性。

## OSC 消息

| 时机 | 默认地址 | 参数 |
|---|---|---|
| 已确认文字变化 | `/chatbox/input` | `[text, True, False]` |
| Enter 发送非空文字 | `/chatbox/input` | `[text, True, True]` |
| 取消或失焦 | `/chatbox/input` | `["", True, False]` |
| 输入或组词 | `/chatbox/typing` | `[True]` |
| 空闲、取消或发送结束 | `/chatbox/typing` | `[False]` |

聊天消息的第二个参数表示立即发送，第三个参数表示通知音。因此，实时同步的文字也会进入游戏气泡，关闭通知音不代表只有自己可见。

发送端使用一个非阻塞 UDP socket，不缓存待发送的预览队列。接收端用 Qt 的 `QUdpSocket` 监听本机相机消息，每轮限制处理数量，避免大量数据占住界面事件循环。UDP 本身不提供送达确认。

文字发送前会去掉 NUL、把换行替换为空格，并限制到 144 个 UTF-16 单元。截断不会留下孤立代理项；这个长度与视觉上的字符数量不一定相同，例如部分 emoji 会占两个单元。

## 菜单和相机判断

菜单防护在每次唤醒时重新检查，不依赖某个按键留下的开关状态。它结合原生菜单、原生编辑控件、鼠标限制区域和相机模式决定是否允许输入。

相机状态来自 `/usercamera/Mode`：非零模式阻止唤醒，0 允许恢复。接收端口默认是本机 UDP `9001`，使用独占绑定；被其他程序占用时会记录警告。

这些信息只能作为外部判断依据。Unity 自绘菜单不一定暴露系统控件，鼠标行为可能随显示模式变化，相机消息也可能丢失。状态未知不代表相机一定关闭。

## 后台运行

控制器定期刷新游戏窗口，并通过前台事件补充发现。应用和游戏监视器各自使用命名互斥量，限制同一用户会话中的重复实例。

自动启动配置写入当前用户的 Windows 登录项。登录模式直接启动应用；随游戏模式运行轻量监视器，约每 3 秒检查一次 `VRChat.exe`，每轮游戏只唤起一次应用。

运行日志使用轮转文件，保存在 `%LOCALAPPDATA%\VRC LinguaBar`。输入条写入 `linguabar.log`，游戏监视器写入 `watcher.log`。退出时会关闭输入会话、移除键盘和前台事件钩子，并释放网络资源。
