# VRC 语伴使用指南

VRC 语伴把文字编辑放在 Windows 输入条中，再把内容送到 VRChat 聊天气泡。使用前，请先在记事本确认所需输入法能正常打字、显示候选词。

## 下载与启动

需要 Windows 10 / 11 64 位和 VRChat PC 客户端。免安装版已经带齐依赖，不需要安装 Python。

1. 在 [Releases 页面](https://github.com/sunzhaocn/VRC-LinguaBar/releases/latest) 下载 **VRC语伴.exe**，保存到固定位置。
2. 在 VRChat 的 Action Menu 中开启 **OSC → Enabled**。
3. 双击 **VRC语伴.exe**，回到游戏按 **Y** 开始聊天。

单文件版已包含运行环境，保存一个 EXE 即可使用。可以直接放到桌面，也可以为它创建快捷方式。

默认聊天目标为 `127.0.0.1:9000`，相机状态接收端口为 `9001`。

启动后程序留在系统托盘，输入条只在需要聊天时出现。更新文件前先右键托盘图标选择“退出”，再下载新版。使用“随 VRChat 启动”时，先把自动启动设为“关闭”，等待约 3 秒，再退出输入条，避免后台监视器占用旧文件；启动新版后可重新开启。移动 exe 后，请从新位置重新设置自动启动。

## 输入与发送

1. 让 VRChat 位于前台，关闭菜单和相机，按 **Y**。
2. 用平时的 Windows 快捷键切换输入法，例如 Win+Space。
3. 输入文字，用数字键、空格、方向键或鼠标完成选词。
4. 按 **Enter** 发送并收起输入条。

按住 WASD 和 Shift 时也可以用 Y 唤出输入条。工具只在识别到 VRChat 窗口时接管这个按键。

输入中文时，可以在微软拼音中输入 `ni hao`，选出“你好”；输入日文时，按日文输入法的习惯输入假名、转换并确认；英文则直接输入即可。候选框的外观、词库和快捷键都由输入法决定。

正在选词时，Enter 会先交给输入法确认候选。候选刚提交后的短暂间隔内也不会发送整句；如果 Enter 没有立即发送，确认选词完成后再按一次。

## 实时同步与取消

**输入条不是私有草稿。** 文字一旦确认进入输入框，就会尝试同步到游戏气泡，不必等到 Enter。尚未选定的拼音、假名等组词内容留在输入法中。

| 操作或状态 | 行为 |
|---|---|
| 编辑已确认的文字 | 同步纯文本，不播放通知音 |
| Enter 发送非空文字 | 发送最终文字，并请求播放通知音 |
| Esc | 取消，尝试清空气泡并关闭输入条 |
| 正在组词时按 Esc | 可能先取消组词，再按一次关闭 |
| 点击其他位置或 Alt+Tab | 取消本次输入；下次打开时从空白开始 |
| 停止输入约 2.5 秒 | 关闭打字指示，输入条保持打开 |

取消时发送的清空消息无法撤回已经被其他玩家看到的内容。UDP 没有送达确认，气泡的最终显示也取决于游戏客户端。

## 菜单与相机

按 Y 时，程序会检查原生窗口控件、鼠标限制区域和收到的相机状态。检测到菜单或相机活动时，会拦住这次 Y，避免输入条和游戏聊天框弹出；原生文本控件中的字母 Y 仍可正常输入。恢复游戏画面后，下次 Y 会重新判断，无需手动开启。

这些判断依赖游戏外部可见的信号，不能读取全部 Unity 菜单状态。相机保护还依赖 `/usercamera/Mode` 消息：收到非零模式时停止唤醒，收到 0 时恢复。端口被占用或消息丢失时，相机状态可能未知或过期。

## 自动启动

右键系统托盘图标，打开 **自动启动**：

| 选项 | 用法 |
|---|---|
| 关闭 | 需要时手动运行 |
| 随 VRChat 启动 | 登录 Windows 后在后台检查游戏进程，约每 3 秒检查一次，发现游戏后运行输入条 |
| 登录 Windows 时启动 | 登录后直接运行输入条，等待游戏出现 |

设置写入当前用户的 Windows 登录项，不需要管理员权限。两个自启模式不能同时开启。选择“随 VRChat 启动”时，监视器也会立即运行；游戏已经打开时同样能识别。

随游戏模式每轮游戏只启动一次输入条。手动退出输入条后，它不会在同一轮游戏中不断重启；关闭并重新运行游戏后，才会再次启动。移动 exe 后，请从新位置重新设置自启。源码用户删除虚拟环境或更换 Python 路径后，也需要重新设置。

选择自动启动时，会一并保存当前的 OSC 地址、端口、相机监听端口、空闲等待时间和日志详细程度。临时指定的 `--vrchat-pid` 不会保存，下次启动会重新识别游戏进程。

## 命令行参数

免安装版可在 exe 所在文件夹中打开 PowerShell，给它添加以下参数：

| 参数 | 默认值 | 用途 |
|---|---|---|
| `--osc-host` | `127.0.0.1` | 聊天消息的目标地址 |
| `--osc-port` | `9000` | 聊天消息的目标端口，1–65535 |
| `--osc-address` | `/chatbox/input` | 聊天 OSC 地址 |
| `--idle-ms` | `2500` | 停止输入后关闭打字指示的等待时间，单位毫秒 |
| `--camera-listen-port` | `9001` | 相机状态接收端口，0 表示关闭监听 |
| `--vrchat-pid` | `0` | 限定 VRChat 进程 ID；0 表示自动识别 |
| `--startup-mode` | 不设置 | `off`、`game` 或 `login`，保存自启选项后退出 |
| `--verbose` | 关闭 | 输出详细日志 |

例如，使用另一组 OSC 端口：

```powershell
.\VRC语伴.exe --osc-port 9100 --camera-listen-port 9101
```

还需要让 VRChat 接收 `9100`、向本机 `9101` 输出相机消息，或通过其他工具转发。仅修改输入条参数不会改变游戏的配置。

没有托盘时，可以这样设置随游戏启动：

```powershell
.\VRC语伴.exe --startup-mode game
```

源码用户可以把 `.\VRC语伴.exe` 换成 `.\.venv\Scripts\python.exe -m linguabar`，参数相同；添加 `--help` 可在终端查看帮助。

## 常见问题

| 现象 | 先检查什么 |
|---|---|
| 双击 exe 提示文件损坏或无法启动 | 从 Releases 重新下载完整的 EXE，并核对 SHA-256 校验文件 |
| 从源码启动提示缺少 PyQt5、pythonosc 或 win32gui | 安装和启动是否使用同一个虚拟环境；重新安装 `requirements-lock.txt` |
| 按 Y 没反应 | 程序是否运行、VRChat 是否在前台、菜单和相机是否关闭，以及是否指定了过期的 PID |
| 输入条有文字，游戏里没有 | 游戏是否启用 OSC，端口是否一致，Chatbox 显示设置是否允许显示 |
| 没有候选框 | 先在记事本测试输入法；确认中英文模式和输入条焦点 |
| 点击候选框后输入条关闭 | 尝试微软拼音或微软日文；第三方独立候选窗可能需要适配 |
| 提示相机 OSC 不可用 | 检查接收端口是否被其他 OSC 程序占用，必要时配置独立输出或转发 |
| 独占全屏下输入条不显示或焦点异常 | 尝试窗口化或无边框窗口模式 |
| 还没按 Enter 就被其他人看到 | 这是实时同步的工作方式，见上文“实时同步与取消” |

输入条日志保存在 `%LOCALAPPDATA%\VRC LinguaBar\linguabar.log`，随游戏启动监视器的日志在同目录的 `watcher.log`。反馈问题时，附上 Windows 版本、输入法名称、游戏显示模式、操作步骤和相关错误日志即可。

退出后台程序请用托盘菜单“退出”。源码用户也可在启动它的终端按 Ctrl+C。收起输入条只结束本次聊天，程序仍会等待下次 Y。

## 开发者：从源码运行

源码支持 Python 3.10 以上版本，免安装发布包使用 Python 3.12 x64 打包。在项目目录运行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m linguabar
```

命令以 Python 3.12 为例。如果没有 `py` 命令，可以用已安装的兼容版本执行 `python -m venv .venv`。之后直接使用虚拟环境内的 Python，无需修改 PowerShell 执行策略。项目目录中的 `vrchat_linguabar.py` 也可作为启动入口。
