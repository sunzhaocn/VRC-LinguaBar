# VRC LinguaBar：测试与兼容性

本记录对应 2026-10-14 的修复。自动化在 Windows、CPython 3.12 x64、PyQt5 5.15.11、python-osc 1.10.2 和 pywin32 312 环境执行。

## 已完成的自动化验证

运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

当前 12 项测试覆盖：游戏先于程序启动和随后游戏窗口变化的目标发现；Y 完整按键只接管一次；系统光标可见和普通 Unity 子窗口焦点不会错误拦截 Y；原生菜单仍会拦截；GUI 线程信息不可用时不会永久禁用 Y；输入条必须拿到真实编辑框焦点；输入条允许激活、打开后关闭立即释放会话；Windows 进程快照；当前用户登录项写入与随游戏监视器启动；启动监视器失败时恢复原设置；监视器在同一轮游戏中只启动一次程序。

另执行 `py_compile`、`git diff --check` 和无游戏的 Qt 启动检查。以上测试只证明对应本地代码路径，未模拟 VRChat 的真实输入、反作弊、显示模式或 OSC 接收。

## 需要在真实游戏中验证

| 场景 | 检查结果 |
|---|---|
| 游戏先启动、软件后启动 | VRChat 在前台按 Y 出现输入条，能够输入和发送 |
| 软件先启动、游戏后启动 | 新游戏窗口出现后按 Y 正常唤醒 |
| 窗口化、无边框、独占全屏 | 输入条可见且键盘焦点进入编辑框 |
| 菜单、相机、原生聊天 | 避免误唤醒；关闭后 Y 恢复 |
| 微软拼音、日文和第三方输入法 | 候选窗出现、选词不误发送、失焦行为正确 |
| 随游戏启动 | 登录 Windows 后启动 VRChat，监视器约 3 秒内唤起程序 |
| 登录自启 | 登录 Windows 后程序出现托盘图标，随后启动游戏可按 Y |
| OSC | 游戏已启用 OSC，预览、最终发送和取消清理符合预期 |

VRChat 内部的 Unity 菜单状态没有公开的完整查询接口；原生菜单检查只能覆盖可观察到的窗口状态。UDP 发送没有游戏端确认。自动启动依赖项目路径与虚拟环境保持有效；移动项目后需重新设置。程序日志位于 `%LOCALAPPDATA%\VRC LinguaBar\linguabar.log`，可用于排查钩子安装、焦点获取及 OSC 错误。
