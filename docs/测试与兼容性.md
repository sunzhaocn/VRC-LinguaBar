# VRC 语伴测试与兼容性

VRC 语伴面向 Windows PC 桌面键盘输入，依赖 Win32 API 和系统输入法。它不能直接在 macOS 或 Linux 运行，也不是 VR 头显内的原生输入界面。

## 运行测试

安装项目依赖后，在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

测试使用 Python 标准库 `unittest`，不需要额外安装测试框架。测试中的窗口、按键和部分 Windows 调用使用替身，不会启动 VRChat。

自动化主要检查以下行为：

- 发现游戏窗口，以及游戏先后启动时的目标更新。
- Y 按下、重复和抬起的处理，包含 Shift 奔跑与菜单防护。
- 输入条焦点获取、会话关闭和资源释放。
- 文字处理、命令行参数与模块入口。
- 聊天 OSC 消息、打字指示和相机状态接收。
- 自启命令、登录项设置和随游戏监视器。

自动化能检查代码路径，不能替代游戏中的输入法体验、焦点切换和 OSC 接收测试。

## 游戏内检查

| 场景 | 观察什么 |
|---|---|
| 先开游戏或先开输入条 | 游戏在前台时，Y 都能唤出输入条 |
| 按住 WASD 和 Shift | Y 可用，松开后不留下重复按键 |
| 打开和关闭菜单、相机 | 活动时避免误唤醒，返回游戏后恢复 |
| 微软拼音、日文或其他输入法 | 候选框可见，选词不误发，点击候选不丢失输入 |
| 中英文及 emoji 混合输入 | 内容正确，长度边界没有异常字符 |
| Enter、Esc、Alt+Tab | 分别发送或取消，输入条按预期收起 |
| 窗口化、无边框、独占全屏 | 输入条可见，焦点能够进入编辑框 |
| 游戏开启 OSC | 实时文字、最终发送和取消清理与操作一致 |
| 两种自动启动模式 | 登录和启动游戏时按所选方式运行 |

## 兼容性说明

Windows 版本、输入法实现、游戏显示模式和其他输入工具都可能影响窗口与焦点行为。第三方候选窗、独占全屏和不同鼠标工具尤其需要实际检查。

相机保护需要持续收到相机 OSC 消息。其他工具占用 `9001` 时，应使用独立端口或转发；单独更改输入条端口不会改变 VRChat 的输出目标。

自动启动依赖项目和 Python 路径。移动目录或重建虚拟环境后，请重新设置。排查时可查看 `%LOCALAPPDATA%\VRC LinguaBar\linguabar.log`，并记录输入法、显示模式和复现步骤。
