# VRC LinguaBar：测试与兼容性

本记录对应项目包中的 `vrchat_linguabar.py`，验证日期为 2026-09-20。

## 1. 验证环境与结果

| 项目 | 本次环境 |
|---|---|
| 系统 | Windows 11 x64，Build 26200 |
| 解释器 | CPython 3.13.15，64 位 |
| 直接依赖 | PyQt5 5.15.11、python-osc 1.10.2、pywin32 312 |
| Qt 运行库与绑定 | PyQt5-Qt5 5.15.2、PyQt5-sip 12.19.0 |
| 自动化测试 | **29 项通过** |
| 实际 VRChat 联调 | 本次未完成 |

测试使用 `unittest`、PyQt5 QtTest、Qt 离屏平台和本机 UDP。界面行为测试使用真实 Qt 控件，但部分 Windows 焦点、菜单与输入法状态由模拟对象提供，不能据此认定真实候选框或游戏菜单已兼容。

| 类别 | 数量 | 覆盖内容 |

原生键盘钩子安装测试使用空目标列表，不主动拦截用户正在操作的游戏。反复销毁测试执行 200 次对象创建和回收，并检查 Qt 对象删除及弱引用释放；它能发现对应路径的对象滞留，不等于证明所有运行场景不存在内存泄漏。

网络测试验证本机收发和编码结果，没有验证 VRChat 服务端传播、其他玩家看到的内容、客户端限流或游戏端清空行为。

## 3. 如何复现

在项目目录中按 README 安装依赖后执行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

预期输出结尾为 `Ran 29 tests` 和 `OK`。测试本身不需要启动 VRChat，也不需要额外安装 pytest。仅支持在 Windows 上运行这组测试。

## 4. 仍需实机验证的兼容性

以下是待验证项目，不是已通过的兼容性承诺。

| 场景 | 应检查的结果 |
|---|---|
| 微软拼音 | 候选框出现；数字、空格、鼠标选词正常；确认候选不误发整句 |
| 微软日文输入法 | 假名输入、转换候选及确认正常；Enter 不误触发最终发送 |
| 第三方输入法 | 候选窗不被当作外部失焦；独立候选进程能否正确识别 |
| 语言切换 | 打开输入条前后切换语言；系统切换面板是否导致输入条取消 |
| 混合文本 | 中日英混合、组合字符、emoji 和临界长度粘贴 |
| 游戏菜单 | 快捷菜单、主菜单、Action Menu、设置子页面、原生聊天等不同 UI 中的 Y 行为 |
| 相机 | 打开相机时阻止唤醒；关闭时自动恢复；监听端口冲突及消息丢失时的表现 |
| 外部失焦 | 点击游戏、点击浏览器、Alt+Tab 后窗口消失；不会抢回用户焦点 |
| 显示模式 | 窗口化、无边框、独占全屏、多显示器与不同缩放比例 |
| 游戏聊天 | 纯文本实时同步、最终通知音、取消清理，以及实际接收频率限制 |
| 长时间运行 | 多次切换世界、重启游戏、反复输入后资源占用与钩子是否正常 |

## 5. 已知限制

- 原生窗口与系统光标检查无法可靠识别所有 Unity 自绘菜单；相机保护依赖 OSC 状态更新。
- 失焦关闭采用事件通知及一次性核验，没有 100ms 轮询看门狗。事件、线程调度和窗口激活都不是硬实时机制。
- UDP 没有送达确认，取消时发送空文本不能保证游戏端在所有情况下立刻清除已有气泡。
- 实时文字通过公开聊天接口发送；Enter 前的文字也可能已被其他玩家读到。
- Windows 10、其他 Python 版本、32 位及 ARM 环境未在本次验证中确认；当前不是 VR 头显内的原生输入方案。
